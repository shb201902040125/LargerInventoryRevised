# 仓库性能优化方案

调用方式见 [指令示例](<InventoryCommandExamples.cs>)。性能数据用同一份负载前后对照，以下依据源码列出成本与优化方向。

| 优先级 | 成本与措施 | 验收重点 |
|---|---|---|
| P0 队列与帧预算 | 记录 FIFO 边界和最早截止位置，划批时仅拉取前缀。维持原有边界优先和截止语义。按命令、页工作量与耗时设软预算，在安全边界让出执行权。见 [队列](<../Backend/Commands/CommandQueue.cs>) 和 [执行器](<../Backend/Commands/CommandExecutor.cs>)。 | 验证连续入队、FIFO、最早截止、截断后的批次、回调顺序。比较深队列每次划批的分配量和帧尾延迟。 |
| P0 主线程保存准备 | 按脏页索引捕获游戏对象的快照。后台串行读取旧文件、校验备份、准备纯数据元信息并提交。无变化的定时保存可跳过，多仓定时保存错峰。见 [仓库](<../Backend/InventoryStore.cs>) 和 [日志](<../Backend/Storage/StoreRedoJournal.cs>)。 | 分别记录快照和写盘阶段，验证提交标记前失败、标记后发布失败、等待重放、备份回退与旧格式。 |
| P1 合并持久化提交 | 先支持同仓多条业务指令一次原子提交。再评估多个独立事务共用一次日志写入，分别结算。物品扣减、交付记录和幂等记录须同一次提交。见 [联机事务](<../Backend/Network/NetworkSystem.Transactions.cs>) 和 [账本](<../Backend/Network/TransactionLedger.cs>)。 | 比较每百条命令的提交次数、写入字节和 P95/P99 延迟。验证回滚、重连回查及逐笔回包。 |
| P1 增量摘要和索引 | 先提供精确计数查询，页列表按需生成。全局索引齐全时直接返回缺失类型的零值。热页可维护空槽位图和按类型的槽位索引，按变更更新摘要。见 [类型索引](<../Backend/Storage/TypeIndex.cs>)。 | 将增量结果与全量重算对照，覆盖修复、收藏、不可用页、模组堆叠规则。 |
| P2 冷启动及联机回包 | 分离文件枚举、纯字节读取和游戏物品反序列化。后台处理前两者，游戏线程按预算推进。引入按字节限额的分页查询及传输公平性。见 [联机协议](<../Backend/Network/NetworkSystem.cs>)。 | 测量冷仓可用时间及大回包期间短查询和交付回执的延迟。 |

## P0 落地状态

- 队列增量跟踪边界和最早截止位置，划批时只分配出队前缀。默认每仓每次指令推进采用 3 ms 和 64 个估算页工作量单位的软预算，在整批清理与回调后检查。
- 异步存档按脏页捕获快照。游戏线程仍负责物品序列化和元数据快照构造，后台负责旧文件读取、备份校验、元数据压缩和日志提交。服务端定时保存按仓错峰，干净且无需重放的仓库跳过定时写盘。
- P1、P2 保留为后续优化项。帧耗时和吞吐收益待实机对照测量。

## P0 回归验证

```powershell
dotnet build LargerInventory.csproj -p:BuildMod=false -p:TargetFramework=net8.0 -p:LangVersion=12.0
dotnet run --project tests/LargerInventory.Tests
```

本次验证为 0 警告、0 错误，58 项回归全部通过。新增用例覆盖边界优先、到期顺序、批次截断、预算让出、干净仓库跳过定时保存及未知存档版本保护。调用示例通过独立编译检查，并由主工程的 `Compile Remove` 与模组打包的 `buildIgnore` 排除。

## 性能验收

用热页读写、跨页取放、深队列、缺失类型查询、多仓同时保存、缺失元数据重建和多人断线恢复作为负载。记录帧耗时 P95/P99、排队等待、事务持久化延迟、交付延迟、分配量、写入字节。物品总量、命令顺序及幂等结果应在优化前后保持一致。软预算在安全执行边界生效，单条命令、单页物品序列化和显式保存的耗时需要单独观察。
